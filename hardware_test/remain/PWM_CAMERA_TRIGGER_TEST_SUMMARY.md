# PWM、1.8 V相机触发与加热功能测试总结

## 1. 文档目的

本文总结 LubanCat 4 硬件PWM的两种用途：

1. 通过IMU6板上的AO3400A驱动八颗330 Ω电阻，实现开环加热和后续恒温控制。
2. 给YLX-2UQ2相机提供外部触发，实现两个成像通道或两台相机同步采集。

两种功能可以使用不同PWM通道，也可以分时测试，但不能在没有核对接线的情况下把相机触发端与加热MOS管栅极混接。

## 2. PWM输出由什么决定

LubanCat GPIO/PWM引脚的高电平由SoC I/O电源域决定，正常约为3.3 V。以下参数的作用不同：

- `frequency`决定每秒脉冲数。
- `duty_cycle`决定高电平时间占一个周期的比例。
- 高电平幅值不是由占空比设置的，正常仍约为3.3 V。
- 万用表直流档通常显示平均值，近似为 `Vavg = Vhigh × duty_cycle`。
- 示波器应分别观察 `Vhigh`、`Vlow`、频率、周期、脉宽和占空比，不能只看平均值。

例如100 Hz、50%占空比的3.3 V PWM：

```text
周期       10 ms
高电平时间 5 ms
低电平时间 5 ms
瞬时高电平 约3.3 V
平均电压   约1.65 V
```

示波器测得空载高电平3.4 V通常属于3.3 V I/O和测量误差范围。若空载高电平变为2.3 V，应检查探头是否使用10×档、示波器是否50 Ω终端、测量项是否选成平均值，以及引脚是否被其他负载或复用功能占用。

## 3. PWM通道确认

先查看系统已启用的PWM控制器：

```bash
ls -l /sys/class/pwm/
```

`PWM(chip, channel)`中的编号对应 `/sys/class/pwm/pwmchipN`，不等同于40针接口的物理脚号。设备树或系统版本变化后映射可能改变，因此必须用示波器确认目标物理脚。

使用现有脚本做有限时间测试：

```bash
sudo python3 hardware_test/camera_sync_pwm.py \
  --pwmchip 3 \
  --channel 0 \
  --frequency 100 \
  --pulse-us 5000 \
  --duration 10
```

以上是100 Hz、5 ms脉宽，即50%占空比。若实际系统中Pin 33对应其他pwmchip，应替换 `--pwmchip`，不能只根据旧代码中的编号判断。

合格判据：

- 目标针脚出现100 Hz波形。
- 高电平约3.3 V，低电平接近0 V。
- 周期约10 ms，高电平约5 ms。
- 10秒后或按Ctrl+C后输出被关闭。

## 4. 第一阶段：空载PWM测试

测试时不连接转换器、相机或IMU6的加热输入：

1. 示波器探头设为10×，输入阻抗设1 MΩ，不使用50 Ω终端。
2. 探头地夹接LubanCat GND，探头尖端接目标PWM脚。
3. 先用1 Hz或10 Hz方便肉眼确认，再提高到目标频率。
4. 记录高低电平、周期、脉宽和是否存在启动毛刺。

推荐初始命令：

```bash
sudo python3 hardware_test/camera_sync_pwm.py \
  --pwmchip 3 --channel 0 \
  --frequency 10 --pulse-us 1000 --duration 10
```

10 Hz、1000 µs脉宽对应1%占空比。正常情况下，高电平仍应约3.3 V，而不是0.033 V。

## 5. 3.3 V转换为1.8 V的要求

YLX-2UQ2触发输入标称1.8 V时，必须保证：

- 空载和带载高电平均处于相机允许范围。
- 低电平满足相机输入低阈值。
- 上升沿和下降沿足够快。
- 转换电路能够同时驱动两个触发输入及连接线电容。
- LubanCat、转换电路和两台相机必须共地。

板上的AMS1117只负责产生IMU电源，不能把3.3 V PWM信号自动转换成1.8 V。电源LDO和数字电平转换器不是同一种功能。

### 5.1 不建议使用几十kΩ电阻分压驱动两台相机

15 kΩ串联、18 kΩ下拉时，空载理论输出为：

```text
3.3 V × 18 kΩ / (15 kΩ + 18 kΩ) = 1.8 V
```

但其戴维南等效电阻约为：

```text
15 kΩ || 18 kΩ = 8.18 kΩ
```

两个相机输入并联、线缆电容、内部下拉或保护电路都会造成明显压降和边沿变慢。已经观察到连接两个相机后，约1.8 V下降到约1 V且不稳定，这不是可接受的正常工作状态，说明现有转换路径驱动能力不足或相机触发输入并非理想高阻。

不要通过继续修改PWM占空比来补偿高电平幅值；占空比改变的是脉宽，不是可靠的逻辑高电平。

### 5.2 推荐转换方案

优先使用具有明确驱动能力的数字电平转换器，例如双电源、方向固定的1.8 V电平转换缓冲器。连接原则为：

```text
LubanCat 3.3V PWM -> 转换器A侧输入
转换器VCCA       -> 3.3V
转换器VCCB       -> 稳定1.8V
转换器B侧输出    -> 两个相机TRIGGER并联点
全部GND          -> 共地
```

转换器输出应靠近分叉点，再以星形方式分别连接两个相机。具体器件必须确认3.3 V输入兼容、1.8 V供电、方向控制和输出电流，不要使用依赖I²C开漏特性的双向MOS管模块驱动推挽高速触发。

如果只做临时台架验证且确认相机输入阻抗足够高，电阻分压可以用于单路慢速测试；但在已经出现带载跌到1 V的情况下，不应继续把几十kΩ分压作为正式方案。

## 6. 第二阶段：转换器空载和假负载测试

不要一开始就连接相机。按以下顺序：

1. 关闭PWM并断电。
2. 连接3.3 V、1.8 V、GND和转换器输入输出。
3. 上电后先确认转换器两侧电源正确。
4. 开启10 Hz、1 ms脉宽PWM。
5. 同时测转换器输入和输出。

预期：

```text
输入：0～约3.3 V
输出：0～约1.8 V
频率和脉宽与输入一致
输出无明显振铃、缓慢爬升或随机抖动
```

如需验证驱动能力，可先接与相机输入相近的已知假负载。若相机输入规格未知，应向厂家确认触发输入阻抗、电路结构、阈值、允许电压和最小脉宽，不要用任意低阻电阻模拟。

## 7. 第三阶段：连接一个相机

断电接线：

```text
转换器1.8V输出 -> 相机A TRIGGER
公共GND        -> 相机A GND
USB            -> LubanCat USB
```

上电后再次测量相机接口处的实际波形。合格判据：

- 高电平接近1.8 V且稳定。
- 低电平接近0 V。
- 脉宽满足相机手册。
- 开启外触发模式后，每个有效触发沿对应一帧。
- 停止PWM后不再产生新曝光帧，或相机按其定义进入等待状态。

## 8. 第四阶段：连接两个相机或两个触发输入

两个触发输入可以并联，但只能并联输入，不能把两个信号输出端互相连接：

```text
                         -> 相机A TRIGGER
1.8V缓冲输出 -> 分叉点 --|
                         -> 相机B TRIGGER

公共GND ----------------> 相机A GND、相机B GND
```

建议：

- 使用星形分支，两个分支长度尽量接近。
- 地线也从公共点分出，避免触发回流绕过USB屏蔽层。
- 示波器分别在相机A和相机B接口处测量，而不是只测转换器输出端。
- 若带载后从1.8 V降到1 V，立即停止测试并更换驱动方案。

## 9. YLX-2UQ2图像采集

### 9.1 安装工具

```bash
sudo apt update
sudo apt install -y v4l-utils python3-opencv
python3 -c "import cv2; print(cv2.__version__)"
v4l2-ctl --list-devices
```

此前出现 `ModuleNotFoundError: No module named 'cv2'`，安装 `python3-opencv`后才能运行采集脚本。

### 9.2 单个2UQ2输出左右拼接画面

如果一个 `/dev/videoN` 输出3840×1080左右拼接图，先在终端A启动采集：

```bash
sudo python3 hardware_test/stereo_2uq2_trigger_capture.py \
  --device /dev/video0 \
  --width 3840 --height 1080 --fps 60 \
  --frames 20 \
  --output 2uq2_sync_capture
```

出现 `ARMED` 后，在终端B启动PWM：

```bash
sudo python3 hardware_test/camera_sync_pwm.py \
  --pwmchip 3 --channel 0 \
  --frequency 5 --pulse-us 1000 \
  --duration 6
```

脚本会把每帧拆成 `left_*.jpg` 和 `right_*.jpg`。

### 9.3 两个独立视频节点

如果两台相机分别对应两个图像节点，先启动：

```bash
sudo python3 hardware_test/dual_camera_trigger_capture.py \
  --cam-a /dev/video0 \
  --cam-b /dev/video2 \
  --frames 20 \
  --output sync_capture
```

出现 `ARMED` 后，再在第二个终端启动PWM。必须先让两个采集线程等待，再发触发脉冲，避免丢失开头帧。

### 9.4 同步结果判定

合格结果至少包括：

- 两路图像数量一致。
- 每个序号均有左右对应图像。
- 运动目标在两图中的位置差符合曝光同步预期。
- PWM触发次数与有效采集帧数一致，允许的启动丢帧应被单独记录。

脚本记录的Linux `monotonic_ns`是USB接收时间，包含USB传输、UVC缓存和Linux调度延迟，不能直接证明曝光沿同步。严格同步应使用：

- 同一个1.8 V触发边沿；
- 相机硬件曝光时间戳或厂家元数据；
- IMU FSYNC/时间戳对应关系；
- 必要时用闪光LED、转盘或示波器曝光指示信号做物理验证。

## 10. IMU加热PWM测试

IMU6加热电路为八颗330 Ω电阻并联，经AO3400A低边开关控制：

```text
等效电阻 = 330 Ω / 8 = 41.25 Ω
100%占空比电流约 = 5 V / 41.25 Ω = 121 mA
100%占空比功率约 = 5² / 41.25 = 0.606 W
```

平均加热功率近似与占空比成正比。先通过SPI `id`和`stream`测试，确认内部温度可读后，才能开启加热。

10%开环测试：

```bash
sudo python3 hardware_test/icm42688_test.py \
  --spi /dev/spidev0.0 --speed 1000000 \
  heater \
  --pwmchip 3 --channel 0 \
  --frequency 1000 \
  --duty 0.10 \
  --duration 30 \
  --hard-limit 45
```

预期平均新增电流约12 mA，ICM内部温度缓慢升高，30秒后PWM自动关闭。确认无异常后才可逐步提高到25%。首板测试不要直接使用100%占空比。

闭环恒温测试：

```bash
sudo python3 hardware_test/icm42688_test.py \
  --spi /dev/spidev0.0 --speed 1000000 \
  closed-loop \
  --pwmchip 3 --channel 0 \
  --target 35 \
  --max-duty 0.50 \
  --duration 300 \
  --hard-limit 50
```

ICM内部温度传感器有绝对偏差，闭环稳定只表示结温读数稳定；首次必须用外部温度计或热像仪核对器件表面和加热电阻温度。

## 11. 当前现象和结论

目前已观察到：

- 空载PWM曾测得约3.4 V，高电平本身基本正常。
- 不同测量条件下曾显示约2.3 V，需要区分示波器高电平测量和平均值，并排除50 Ω终端及外部负载。
- 转换后空载约1.8 V，但连接两个相机后降到约1 V且波形不稳定。

因此目前PWM控制器本身不一定存在故障，主要问题是1.8 V转换/驱动路径的带载能力不足，或者相机触发接口内部存在明显负载。两相机同步测试应暂停在“转换器带载合格”这一门槛，不能把约1 V的不稳定波形继续作为有效触发电平使用。

## 12. 安全和操作要求

- 所有接线修改必须断电完成。
- 相机触发输入不得直接承受3.3 V，除非厂家明确允许。
- 不要把LDO输出与其他1.8 V电源硬并联。
- 不要同时运行两个占用同一pwmchip/channel的程序。
- 使用有限的 `--duration`，程序退出后确认PWM已关闭。
- 加热测试必须限流、限占空比、限时间、限温，并有人值守。
- `kill -9`、系统死机或掉电不能保证Python的 `finally`执行，硬件栅极下拉和电源限流必须有效。
